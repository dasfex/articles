# Военный синус: когда C++ показывает свой характер

*История о том, как простая математическая функция может превратиться в детективную головоломку*

---

## Пролог: что такое военный синус?

В физике есть задачи, где синус может принимать значения больше единицы. Например, маятник, подвешенный на центре вращающейся платформы — выводишь абсолютно нормальную тригонометрическую формулу, подставляешь два оборота в секунду, пятьдесят сантиметров длины, и получаешь синус порядка 1.6.

Отец рассказывал, что у них на военной кафедре, когда синус в промежуточных вычислениях получался 2 или 2.5, полковник даже не останавливался.

К сожалению, создатели C++ о военном синусе ничего не знают. В их мире синус — это обычная функция: `float`, `double`, `long double`, и ещё есть весёлая специализация для целочисленных типов, чтобы они знали, какой из вариаций синуса вызывать.

Но у нас ситуации бывают разные.

## Эксперимент первый: создаём военный синус

Нам нужен военный синус — пусть он всегда возвращает 1.5. Мы его объявили:

```cpp
#include <iostream>
#include <cmath>

double sin(float x) { return 1.5; }
double sin(double x) { return 1.5; }
double sin(long double x) { return 1.5; }
double sin(int x) { return 1.5; }

int main() {
    std::cout << std::sin(float(0.5)) << std::endl;
}
```
[https://godbolt.org/z/P8rM4Keca](https://godbolt.org/z/P8rM4Keca).

Для трёх компиляторов:
```
0.479426
```

Слава богу, у нас в C++ есть пространства имён! 
То есть я вызываю синус из стандартного `namespace`, подставляю туда `float` — результат выполнения есть самый обычный синус, никаких моих военных. 
Мы вызываем везде синусы из стандартной библиотеки.

Аналогично вызываем синус `double`: [https://godbolt.org/z/c3zMb56YG](https://godbolt.org/z/c3zMb56YG). 

Получаем странную магию. Хотя на clang всё как и ожидается, на gcc и icc мы видим такое:
```
0.479426
1.5
```
Внезапно синус стандартной библиотеки поломался и стал военным!

## Эксперимент второй: проверяем все типы

Проверяем: [cppreference sin](https://en.cppreference.com/w/cpp/numeric/math/sin). 
Точно есть синусы от `long double`, `float` и целочисленных типов. Уже подозрительно. 

Заведём оставшиеся примеры — синус от `long double`, синус от `int`. [https://godbolt.org/z/aEa3qf7qj](https://godbolt.org/z/aEa3qf7qj). 

Всё стало ещё интереснее. 
```

gcc -O2 -std=c++20

icc -O2 -std=c++20
```

Синус стал 1.5.

Если покрутить флаг оптимизации, то мы увидим туда-сюда праздноизменяющиеся значения в ответе. 
Но избавиться от военного синуса никак не получится!

Мы как опытные разработчики знаем, что это обычно значит — скорее всего мы зашли куда-то в область undefined behaviour, и наша замечательная оптимизация чего-то там навыдумывала, вычистила и так далее. 
Давайте уберём оптимизацию:
```
0.479426
1.5
0.479426
1.5
```
и всё станет ещё хуже! 
Теперь все компиляторы абсолютно одинаково ломаются.

Можно попробовать добавить warning'и c `-Wall -Wextra`, но компиляторы нам ничего про проблемы с пространствами имён не скажут. 

## Маленький спойлер

Я добавил ещё две реализации — `sinf` и `sinl`:

```cpp
#include <iostream>
#include <cmath>

double sin(float x) { return 1.5; }
double sin(double x) { return 1.5; }
double sin(long double x) { return 1.5; }
double sin(int x) { return 1.5; }
float sinf(float x) { return 1.5; }
long double sinl(long double x) { return 1.5; }

int main() {
    std::cout << std::sin(float(0.5)) << std::endl;
    std::cout << std::sin(double(0.5)) << std::endl;
    std::cout << std::sin((long double)(0.5)) << std::endl;
    std::cout << std::sin(int(0.5)) << std::endl;
}
```

[https://godbolt.org/z/7rfaYTz93](https://godbolt.org/z/7rfaYTz93).

```
1.5
1.5
1.5
1.5
```

Теперь у нас без оптимизации просто все синусы стандартной библиотеки поломались и стали военными! 
С оптимизацией — кто во что горазд.

## Анализ: что происходит в стандартной библиотеке?

Реакция нормального человека на это дело — "А?". 
К сожалению, столько лет работая в C++, нормальным меня назвать сложно, поэтому надо докапываться.

В первую очередь закомментируем все наши реализации, посмотрим, во что превращается эта программа в бинарном коде. 
[https://godbolt.org/z/88Eezv9Kr](https://godbolt.org/z/88Eezv9Kr).
И замечаем интересную вещь: у нас в исходном коде для `float` вызывается синус (`call    std::sin(float)`), для `long double` вызывается синус (`call    std::sin(long double)`), а для `double` почему-то не `std::sin`, а синус из глобального `namespace` (`call    sin@PLT`). 
И там чуть ниже для `int` — честная специализация синуса для `int` (`call    __gnu_cxx::__enable_if<__is_integer<int>::__value, double>::__type std::sin<int>(int)`).

> Я опущу небольшой кусочек Пашиного расследования и перемещусь к открытию.

Посмотрим на libstdc++ реализацию хедера cmath: https://www.cs.auckland.ac.nz/references/c/libstdcpp-api/a01013_source.html. 
Найдём в ней синусы. 

У нас есть действительно синус от `float`, который объявлен и возвращает `__builtin_sinf`. 
У нас объявлен синус от `long double`, который возвращает `__builtin_sin`. 
Для `int` — это шаблонная магия, она обозначает, что тип `T` у нас целочисленный, и он возвращает `__builtin_sin`.

А вот для `double` мы почему-то поленились написать ещё одну функцию и вместо этого мы импортируем все синусы из глобального пространства имён:

```cpp
using ::sin; // Импорт из глобального namespace
```

С точки зрения C++ это значит, что все синусы, которые объявлены в глобальном `namespace`, мы можем использовать в стандартной библиотеке. 
А с точки зрения исходного кода это означает, что мы ищем символы синуса из глобального `namespace`.

## Бонусная дурка 2

А теперь квинтэссенция всего, что можно найти вокруг военного синуса. Вот у нас есть программа:
```cpp
#include <iostream>
#include <cmath>

double __attribute((weak))
sin(double x) { return 1.5; }

int main() {
    std::cout << "double: " << std::sin(double(0.5)) << std::endl; // 0.479426
    std::cout << "integer: " << std::sin(int(0.5)) << std::endl;   // 0
}
```
[https://godbolt.org/z/Pzcjv7rx8](https://godbolt.org/z/Pzcjv7rx8). 

Я привёл просто военный синус с атрибутом `weak`, вызвал синус от `double` — он посчитался честно, 0.479426, и с `integer` тоже всё честно: округлили 0.5 вниз и взяли синус. Всё хорошо. 

А теперь давайте закомментируем вызов синуса от `integer` — больше ничего не поменялось, только этот комментарий:

```cpp
int main() {
    std::cout << std::sin(0.5) << std::endl;     // Что выведет?
    // std::cout << "integer: " << std::sin(int(0.5)) << std::endl;
}
```
Внимание, вопрос: поменяется ли и синус от `double`?
```
double: 1.5
```
Конечно да! Я бы это не показывал, если бы это было не так. [https://godbolt.org/z/MqnT53jdY](https://godbolt.org/z/MqnT53jdY). 

Эта штука воспроизводится только на компиляторе ICC. 
В ICC достаточно сложно разобраться, что происходит, информации катастрофически меньше по сравнению с GCC и Clang, и честно говоря, не очень сильно хочется. 
Но просто сам факт, что можно закомментировать вызов какой-то функции и поменять результат работы другой функции — это абсолютно прекрасно.

Где-то в этот момент я услышал сирены скорой и решил, что пора с этим прекращать и не раскапывать дальше. А то скоро в дурке прибавится одним постояльцем.

## Выводы и уроки

Выводы из всего этого можно сделать следующие:

1. **Не используйте глобальный namespace вообще никогда** — вы можете им поломать абсолютно случайно что-то неожиданное. Мало ли какие там функции ещё объявлены в глобальном namespace, а в стандартной библиотеке используются там `using` из глобального `namespace`.

2. **Оптимизации тоже не стоит доверять** — перепроверяйте, там везде всё разное.

3. **Авторам библиотек тоже нельзя доверять** — они на выдумку горазды.

4. **Создатели компиляторов очень по-разному понимают, что и как надо оптимизировать** — и хотелось бы тоже перепроверять.

5. **И за собой тоже перепроверяйте** — потому что я тут чуть было чушь не нагородил из-за того, что неправильный флаг поставил в своих экспериментах.
